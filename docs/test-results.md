# 3.5.1 验证记录

日期：2026-10-21。以合并后的 3.5.0 为基础，对照历史 3.4.1 的发送逻辑调整。所有测试均使用本地 HTTP、WebSocket 和 DOM 样例，没有访问学校或提交真实选课。

构建成功，44 项单元／模拟页面测试通过。可安装文件版本为 3.5.1；源码、构建脚本及安装文件一并提交。

## 行为核对

| 场景 | 验证内容 |
| --- | --- |
| 同步单个／分组 | HTTP 返回后计算间隔，不等待最终队列结果 |
| 异步单个／分组 | 前一请求未返回时，按间隔发送下一门／组 |
| 待处理课程 | 同一教学班提交中、排队中、未知时不重复发送 |
| 循环 | 无可发送课程时等待现有结果，明确失败后继续尝试；保留循环次数 |
| 入队与成功 | HTTP 200 仅入队，最终推送或已选记录确认后移除 |
| 无推送连接 | 不拦截提交，超时后查询已选记录 |
| 301 | 用户确认后使用同一教学班 ID；停止或取消后不发确认请求 |
| 停止与异常 | 不派发后续课程；未决写入保留状态；迟到推送仍能结算 |
| 默认与恢复 | 恢复 300／350／1000／500 ms 默认值，已有设置不覆盖，不保存凭据 |
| 页面与安装文件 | 两类模拟布局、按钮绑定、原面板、设置与悬浮入口 |

移除了按志愿轮次、实验班和教材标记直接拦截的分支，提交参数仍是原有字段，没有新增这些业务选项的处理逻辑。此项验证的是不再提前拦截，不代表模拟响应可证明学校接受所有特殊课程。

本次保留独立队列结果等待，HTTP 发送完成后不占用下一门的调度；停止时统一取消并等待任务收尾。每轮结束等待在途 HTTP 结束，不等待所有课程的最终队列结果；全部剩余课程都在排队时，才等待结果变化。

3.4.1 的成功入队即删除、301 错误 ID、异步请求不跟踪等问题没有恢复。历史 v4.0.1 实验工程未重新引入。3.5.0 安装文件保留作为本次修改前的基线。
